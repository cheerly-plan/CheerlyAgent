# 深度分析外部结构化事实清单（deep-facts/v1）

## 这条通道解决什么

`report/deep/` 的 10 章分析里，第 2/3/4/6/7/9 章需要近 5 年年报附注、审计
报告与关键审计事项、交易所问询函及回复、行业原始统计。事实层底稿只覆盖
本期/基期财报，因此这些章节在默认数据条件下只能诚实地输出缺口。

**核心约定（2026-11-08 决策 ②③）**：

1. 外部数据源优先级：**近 5 年定期报告 → 审计报告 / 问询函 → 行业统计**；
2. **库里有一份 PDF ≠ 附注数字已抽出**：只有人工核对原文后录入的
   **结构化事实清单**才能进 `SourceLedger`；
3. 盘点层**只报覆盖度与缺口**，不抽数字、不补值、不假装数据存在；
4. 绝不让 LLM 现场从 PDF 抽数——那会把幻觉重新引入零幻觉门禁。

## 目录与启用方式

| 项 | 值 |
| --- | --- |
| 默认目录 | `data/deep_facts/`（与 `data/reports/` 同级） |
| 覆盖方式 | 环境变量 `REPORT_DEEP_FACTS_DIR` |
| 文件格式 | `.json` / `.jsonl`，只扫描目录顶层，单文件 ≤ 2 MB，总事实 ≤ 500 条 |
| 启用入口 | HTTP 同步/异步端点、聊天工具生成入口（显式挂载）；库级 `DeepOptions(facts_dir=...)` 需自行传入 |
| 目录不存在 | 由 `LocalFactsProvider` 记一条缺口，报告照常生成，不假装有数据 |

`data/` 整体被 `.gitignore` 忽略：清单属于**本地数据**，不随代码提交，
生产环境通过外挂数据卷或发布流程投放。仓库里的 `docs/deep_facts.example.json`
只是格式模板，不要当成真实数据使用。

## 字段规范

`.json` 顶层可以是数组，也可以是 `{"meta": {...}, "facts": [...]}`；
`.jsonl` 每行一个对象，允许 `#` 开头的注释行。`meta` 不参与校验。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `item` | ✅ | 指标/事实名称，如 `营业收入`、`关键审计事项数量` |
| `value` | ✅ | **原文出现过的数字或表述**，不得换算、不得心算、不得写同比/差值/占比 |
| `source_file` | ✅ | 源文件名，建议带知识库 `file_id`（如 `…报告（3dce4257-…）`） |
| `level` | 建议 | `L1`–`L6`，默认 `L1`；非法值按最保守的 `L4` 处理并报警告 |
| `backtrace_to` | L4/L5/L6 必填 | 二手数据必须写出回溯到的 L1–L3 原件，否则台账拒绝入表 |
| `location` | 严格档必填 | 页码/附注号，如 `第88页 四、季度财务报表`；`第(\d+)页` 会被解析成结构化页码 |
| `quote` | 严格档必填 | 原文片段，供审核员逐字核对数值 |
| `subject` | 建议 | 标的全称，用于按 target 过滤；缺省时不过滤 |
| `period` | 建议 | 报告期，如 `2026Q3` / `2025Y`；含年份时按近 N 年窗口筛选 |
| `acquisition` | 可选 | 获取方式，缺省 `外部数据源/<doc_type>` |
| `doc_type` | 可选 | `periodic` / `annual` / `audit` / `inquiry` / `industry_stat` / `other`；缺省按文件名推断 |
| `chapters` | 可选 | 该事实服务的章号数组；缺省按 `doc_type` 映射 |

`value` 的合法示例：`1,614,059,366.89元`、`-205,260,194.78元`、`120万片`。
非法示例：`同比增长 34.31%`（心算）、`约 16.14 亿元`（手工换算）、
`较年初增加 1,590,880,071.51元`（差值推导）。

> 单位换算由台账自己确定性派生（`derived_number_forms()`），**清单里不要预先换算**。

## 三步工作流

```bash
# 1) 从已校验的溯源附件确定性导出（零 LLM、零 PDF 解析）
uv run python scripts/export_deep_facts.py
#    只看 *.provenance.md 的原文金额行，跳过 akshare 摘要/推算比率/无页码行
#    可用 --exclude-period 2026Q3 避免与本期事实层台账重复
#    可用 --dry-run 先统计

# 2) 人工核对新增条目，然后静态门禁
uv run python scripts/validate_deep_facts.py --check-kb
#    严格档：缺页码/原文/回溯链、level 非法、条目重复都非零码退出
#    --check-kb 额外核对 source_file 能否对应知识库已入库原件

# 3) 生成报告（HTTP / 聊天工具入口已默认挂载该目录）
#    POST /v1/report  或  POST /v1/report/jobs
```

人工录入新事实时，建议按「一份源文件一个 `.jsonl`」组织，每条都带
`location` + `quote`；先跑 lint 再入库。

## 运行时行为与门禁链

```
清单文件 → LocalFactsProvider（结构校验 / 去重 / 年份与 subject 过滤）
        → collect_sources（与知识库盘点、行业统计 fetcher 合并）
        → SourceLedger.add_external（L4/L5/L6 回溯门禁，唯一准入门）
        → 章节分析的数字白名单（allowed_numbers）
        → 推断层 PDF 的零幻觉门禁
```

- **候选 ≠ 入表**：被台账拒绝的条目写进 `SourceLedger.rejected` 与缺口，
  执行报告里以「外部事实准入：N 条候选 / M 条入表 / K 条拒绝」可见。
- **覆盖度报告**按优先级逐类列出「源文件 N 份 / 结构化事实 M 条」；
  「有源文件但零结构化事实」会单独记缺口，不会把 PDF 存在当成数据齐备。
- `periodic`（季报/半年报）与 `annual`（年报）分开计数：半年度报告不再
  被误判成年报，避免凭空消掉「近 5 年年报未入库」这条真缺口。
- 清单文件解析失败、条目缺必填字段、可溯源要素缺失，都记进
  `execution.notes` / `ledger_gaps`，推断层 PDF 可见，**绝不静默丢弃**。

## 不做什么

- 不解析 PDF 附注、不抓取第三方站点、不内置外部 API 端点；
- 不把知识库里的文件当成已抽出的事实；
- 不在清单层做单位换算、同比/环比、插值或缺值填补；
- 不为推断层另开弱门禁：所有外部事实与正文数字走同一套台账与白名单。
